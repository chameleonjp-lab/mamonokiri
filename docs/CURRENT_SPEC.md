# 現在の仕様 — 墨霞の剣（mamonokiri）

更新日: 2026-09-11。品質改善計画の第1〜5段階（起動・時計・状態、危険域・固定移動・カメラ、斬撃・命中・演出・複数指、得点・ランキング、安全稽古・初期選択・結果導線）を反映。
このファイルは、このブランチの実装済み仕様をまとめる。旧 `PLAN.md` や監査資料は変更の経緯として扱い、未実装の改善案を現行仕様と混ぜない。

## 遊びと操作

敵の予告に対して左右回避または防御を選び、通常斬撃と反撃で倒して進む。画面の「左・右・斬・防」を維持する。通常斬撃は離れた敵へ飛刃を送る方式。画像やテクスチャを使わず、コードから作った山伏と敵をBabylon.jsで表示する。

名前は開始前に必須。名前は制御文字を除去し、前後空白を除いた20文字まで。最初の3体でも斬を押すと攻撃が出る。課題未達成を理由に斬撃を無反応に戻さない。

タイトルの初期選択は十番勝負・見習い。勝負の長さ、難易度、端末設定は追加設定へ折りたたみ、名前入力と新しく始めるを先に示す。別導線の「稽古を試す」は最初の3体を安全に試す非ランキング・非記録の短い経路で、見習い固定。稽古中に被弾しても体力と構えを戻し、正式勝負へ不利を持ち越さない。稽古は飛ばせ、結果から正式勝負へ進め、タイトルへ戻って後から再挑戦できる。

モードは十番勝負・二十五番・五十番、難易度は見習い・修験・無明。初期選択以外は追加設定から選ぶ。各モードの表示名・体数・難易度の係数は `client/src/game/rules.ts` の `RUN_MODE_CONFIG` と `DIFFICULTY_CONFIG` を正とする。

## 戦場・レーン・カメラ

戦場の左右の安定位置は、左 `-0.9`、中央 `0`、右 `0.9` の3レーンで固定する。左右ボタンは画面比に応じた距離ではなく、押した方向の左右レーンを目的地にする。移動中だけ中央を通過し、移動完了後に座標が累積して外側へ広がることはない。敵の巡回範囲と急降下の目標も同じ左右端を使う。

左右攻撃の危険域の中心、強い予告線、攻撃範囲、足元のレーン表示は、`COMBAT_LANE_SPACING` と攻撃計画の `dangerLane` から作る。狭い左右攻撃では中央レーンを危険域に含めず、広域攻撃と中央攻撃では中央を含める。追尾やフェイントで計画が変わった場合は、表示と判定に同じ新しい計画を使う。

カメラは戦闘座標を変更せず、表示領域だけを画面比に合わせる。縦長では基準位置から少し遠ざけ、横長では基準位置を保つ。画面サイズが変わったら再計算し、戦闘中の移動範囲や敵の危険域を変えない。カメラ調整は表示上の収まりを改善するものであり、iPhone Safariの実画面確認が済むまでは完成扱いにしない。

## 起動

タイトルは3Dの初期化が成功しなくても残す。`SceneStatus` により、準備中・準備完了・失敗を区別する。名前、モード、難易度、端末設定の操作は準備中も可能。

「新しく始める」は最初の3D描画が成功するまで無効。処理側も準備完了を確認し、開始イベントだけが先に失われる状態を防ぐ。準備に失敗した場合は理由の案内と「画面の準備をやり直す」を表示する。再試行で名前・選択内容を消さない。

失敗・再試行・画面破棄では、その試行が持つシーンと描画エンジンを破棄する。破棄後にシーン作成が完了しても、古い試行を準備完了として通知しない。シーン破棄時には遅延した演出・音の処理も取り消す。画面全体の予期しない描画エラーには、日本語の説明とページの再読込ボタンを出す。

## 勝負内の時計

`client/src/game/clock.ts` の `RunClock` を戦闘時刻の基準とする。勝負開始・再挑戦で0msへ戻し、約16.667msずつ（1秒に60回）進める。ブラウザの描画頻度から独立し、通常の更新遅れは必要な回数の小さな更新へ分けて処理する。入力の直前にも時計を進め、描画が来ていなくても長い中断を検出する。

攻撃、敵予告、ガード、受け流し、回避、構えの回復、連撃期限、敵切替はこの時計を読む。日時は新しい敵順の生成にだけ使う。React側のスワイプ所要時間と二重タップ抑止はブラウザの時刻を使うが、戦闘の命中期限には使わない。

最初の敵の攻撃待ち時間は勝負開始から、次の敵は各生成時刻から測る。待ち時間はその敵のcooldownと難易度係数で決まり、タイトルの滞在時間に依存しない。予告開始は待ち時間を超えた最初の更新時点。敵の種類が異なる場合、待ち時間も異なる。

表示・記録用のプレイ時間は、戦闘が進んだ更新時間だけを数える。一時停止中・敵切替中・結果中を含めない。勝負内の時計自体は、停止していない敵切替や結果の短い動作にも使う。

## 攻撃・命中・演出・入力

通常斬撃・反撃・防御崩し・大崩れへの強撃は、開始時に攻撃種・開始時刻・命中時刻を予約する。`rules.ts` の `startup` が振り始めから命中までの基準であり、通常斬撃だけは飛刃の到着分を加えてから命中する。反撃・防御崩し・強撃はボタンを押した瞬間に体力を減らさず、命中時刻に一度だけダメージ、構え、得点、命中演出を解決する。

短いヒット演出はゲーム時計や攻撃更新を止めない。演出設定はカメラ揺れ・エフェクトの表示量だけを変え、同じ入力と時計なら体力・得点・命中結果は変わらない。飛刃メッシュは命中、敗北、再挑戦、破棄時に片付け、材質 `flying_slash` はシーン内で共有する。

守備成功の得点

受け流しと危険線に対する正しい回避は、同じ敵に対する有限の守備加点枠を共有する。通常敵は3回、ボスは6回まで加点し、上限後も受け流しの反撃受付、構え回復、回避の移動は有効である。結果画面には勝負全体の守備加点回数を表示する。連撃、無傷撃破、空振りなしの加算はこの枠とは別で、`scoreForCombo` の上限も維持する。

戦闘面のスワイプは、最初に開始した指の `pointerId` を予約する。別の指の `pointerup`・`pointercancel` は無視し、開始指の終了・取消時だけ捕捉を解除する。ボタンは既存の `pointerdown` 経路で一度だけ操作を送り、合成クリックによる二重入力を抑止する。画面の実タッチ感覚はiPhone 17 Pro Safariで別途確認する。

## 一時停止と復帰

手動停止、ページ離脱・復帰、表示状態の変化、タイトルに戻る操作、戻る確認で時計を止める。操作受付も止め、攻撃や反撃の期限を停止時間分ずらす方式は使わない。停止中に時刻が進まないため、期限の残りが保たれる。

前回処理から250msを超えた場合は自動停止する。遅れた時間をまとめて消化したり、期限を越えた攻撃を黙って削除したりしない。最後に処理した状態を残し、`pauseReason: "frame-gap"` を画面へ通知する。250msちょうどまでは小さな更新に分けて処理する。この閾値は実機計測後の調整対象。

中断後は「再開」を押して復帰する。再開操作後の700msはゲーム時刻と操作受付を止め、それから続きを進める。復帰猶予中に押した操作は予約しない。章報酬の選択後は通常の敵切替へ進む。停止時に残った未処理のフレーム時間を、後の再開へ持ち越さない。

短いヒット演出はゲーム更新を止めない。停止するのは手動停止、ページ離脱・復帰、表示状態の変化、タイトルへの移動、戻る確認だけである。

## 戦闘と進行の継続仕様

通常斬撃・反撃・防御崩し・大崩れへの強撃がある。攻撃時間・startup・active・recoveryの数値は `rules.ts` の `attackTimingFor` を正とし、シーンの共通予約時刻で一度だけ命中させる。画面比によるカメラの実機確認と、全攻撃種のSafari実操作は未確認である。危険域と移動距離は第2段階で固定した。

敵は通常7種類とボス10種類の定義を持つ。5体ごとのボス、10体ごとの章報酬、同じ敵順での再挑戦を維持する。敵順の乱数と戦闘中の乱数は別に管理する。章報酬は次の章のみに適用する。

## 保存と通信

`client/src/game/storage.ts` で保存へのアクセスをまとめる。保存機能へのアクセス自体、読み取り、書き込み、削除の例外を受け止める。保存できないときは初期値とページ内の値を使い、タイトル・設定操作・勝負・結果を続けられる。

一度保存失敗を検出したら、タイトル・停止画面・結果に「名前・設定・記録をこのブラウザに保存できません」と説明する。ページ内で変更した値や自己最高は保持するが、ページを閉じた後の保持は保証しない。名前を消す操作も、以前の名前が再度出ないようページ内で保持する。以前の保存キーや記録形式は変えない。

端末内の自己最高はモード・難易度・得点規則版別。現在の版は `mamonokiri-score-v2` として旧ローカルキーを読み替えず、新しい記録と比較しない。共有文と実験場リンクを維持する。共有ランキングは `supabase/migrations/20260911000000_mamonokiri_scoped_ranking.sql` の専用テーブル・RPCを使い、モード・難易度・`mamonokiri-score-v2`・勝負ID（UUID）で条件を分ける。旧`game_scores`の記録は読み替えず、そのまま残す。同じ勝負IDの再送は重複登録せず、内容が違えば拒否する。

結果画面では記録・統計、直前の失敗理由、次に試す一つの行動、再挑戦を先に表示する。正式勝負では「もう一度遊ぶ」「同じ敵順で再挑戦」「最初の画面へ戻る」を、稽古では「稽古をもう一度」「正式な勝負へ」「最初の画面へ戻る」を表示する。正式勝負のスコア送信の状態とランキング読込の状態は分けて表示する。送信に失敗しても結果と読込済みランキングを消さず、「スコアを再送信」から同じ勝負IDで再試行できる。稽古の結果は自己最高・オンラインランキングへ送信しない。前の勝負の非同期応答は、次の勝負の結果へ反映しない。Supabase migrationの本番適用までは新RPCが利用できないため、送信失敗を結果画面で明示する。
